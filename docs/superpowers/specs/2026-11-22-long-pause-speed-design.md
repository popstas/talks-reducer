# Long pause speed — design

Status: draft, awaiting approval. Date: 2026-11-22.

## Зачем

На записях бывают долгие периоды, когда идёт неинтересная работа скриптов:
микрофон выключен, изредка звучат уведомления. Сейчас час такой тишины на
скорости тишины ×10 сжимается до 6 минут, а нужно до 3 минут. Нужна вторая,
абсолютная скорость для длинных пауз.

## Цели

- Пауза длиннее порога (по умолчанию 60 с) идёт на отдельной скорости
  (по умолчанию 20), а не на `silent_speed`.
- Короткие звуки внутри длинной паузы (уведомления, редкие реплики) её не
  обрывают: весь отрезок вместе с ними идёт на длинной скорости. Реплики на ×20
  становятся неразборчивыми, и это допустимо.
- Настройка в Advanced-окне GUI одной строкой с чекбоксом и в CLI, передаётся
  на remote-сервер.

## Не цели

- Поле в пресетах, Simple mode, Web UI и OBS dock: такие записи делаются только
  в Advanced или CLI. Поэтому не нужна миграция пресетов.
- Множитель от `silent_speed`: скорость абсолютная.
- Ограничение длины паузы в результате («не длиннее N секунд»).

## Анти-цели

- Выключенная функция меняет результат: путь по умолчанию должен остаться
  прежним байт в байт.
- Настройка, запомненная в Advanced, тайно действует в Simple mode, где её не
  видно.
- Remote-сервер старой версии молча игнорирует настройку, и пользователь
  получает файл без ускорения длинных пауз.

## Подходы (выбран B)

- A. Ускорять только сплошную тишину длиннее порога. Уведомление делит паузу
  на две и играет на ×1. Самый простой вариант, но результат зависит от числа
  уведомлений (час с десятком уведомлений сжимается примерно до 3 мин 15 с).
- **B. Ускорять длинный отрезок целиком. Выбран.** Звучащие фрагменты не длиннее
  допуска (2 с) поглощаются окружающей тишиной; если весь отрезок длиннее
  порога, он идёт на длинной скорости. Гарантирует нужный результат.
- C. Ограничение длины паузы в результате. Отклонён: нужна абсолютная скорость.

С «Speedup no voice» уведомления и так считаются тишиной, там A и B совпадают.

## Что решено

### Пайплайн

- `chunks.py`: новый индекс `LONG_PAUSE_SPEED_INDEX = 3` и чистая функция
  `apply_long_pauses(chunks, min_frames, tolerance_frames)`. Она находит
  отрезки, которые начинаются и заканчиваются тихим чанком, а внутри содержат
  только звучащие чанки длиной ≤ `tolerance_frames`; отрезок от начала первого
  до конца последнего тихого чанка длиной ≥ `min_frames` склеивается в один
  чанк с индексом 3. Остальные чанки не меняются.
- Вызывается в `pipeline.py` сразу после `build_chunks` и **до**
  `apply_remove_ranges`, чтобы вырезанные фрагменты оставались вырезанными.
- `new_speeds` становится `[silent, sounded, inf, long_pause_speed]`. Аудио
  (`audio.py`) и `setpts` (`get_tree_expression`) берут скорость по индексу и
  отдельной поддержки не требуют.
- Допуск звука — внутренняя константа `LONG_PAUSE_SOUND_TOLERANCE_SECONDS = 2.0`.
  Длина звучащего чанка уже включает поля `frame_spreadage`, поэтому
  уведомление в 1 с укладывается. **Моё решение:** отдельной настройки нет.
- Функция включена, только если задана `long_pause_speed`. Проверка
  `neutral_speeds` (обе скорости 1.0 → без обработки аудио) учитывает её: при
  включённой функции путь неактивен, так что «No speedup» плюс длинные паузы ×20
  работает.
- `long_pause_speed <= silent_speed` → функция пропускается с записью в лог
  (иначе длинные паузы шли бы медленнее коротких). **Моё решение.**
- Лог: `Long pauses: 3 stretches, 52.1 min at x20`, или `Long pauses: none
  longer than 60 s`. Эта строка служит и маркером для remote-проверки (ниже).

### Настройки

`ProcessingOptions`:

| Поле | По умолчанию | CLI |
|---|---|---|
| `long_pause_speed: Optional[float]` | `None` (выключено) | `--long-pause-speed SPEED` |
| `long_pause_seconds: float` | `60.0` | `--long-pause-seconds SECONDS` |

`--long-pause-seconds` без `--long-pause-speed` ничего не включает.

### GUI

- Строка в панели basic options (видна в Advanced, скрыта в Simple mode
  вместе с панелью), сразу под строкой **Silent**:
  `[✓] Speedup x[20] pauses longer than [60] seconds`. Это чекбокс, затем
  `ttk.Entry` скорости, надпись, `ttk.Entry` секунд и надпись `seconds`.
- Переменные `long_pause_enabled_var`, `long_pause_speed_var`,
  `long_pause_seconds_var`, сохраняются в `GUIPreferences` как
  `long_pause_enabled` (по умолчанию `False`), `long_pause_speed` (20) и
  `long_pause_seconds` (60).
- Поля ввода применяют значение по Enter и при потере фокуса, с ограничением
  диапазона (скорость 1–100, секунды 5–3600; **моё решение**); при нечисловом
  вводе возвращается последнее принятое значение (как у `…`-слота
  `SegmentedChoice`). При снятом чекбоксе поля неактивны.
- Строка не входит в `_basic_defaults`/`_basic_variables`: макрос
  **Silence ×5** и подсветка basic-пресетов её не трогают, и она не переводит
  выбор пресета в **Custom** (это не поле пресета).
- `_collect_arguments` передаёт `long_pause_speed`/`long_pause_seconds`, только
  если чекбокс включён и Simple mode выключен.
- `cut_marks_ui.remove_only_overrides` удаляет оба ключа: проход «только
  вырезать» не должен ускорять паузы второй раз.
- Заголовок блока конверсии в логе (`format_conversion_header`) при включённой
  функции добавляет `long pauses x20 >60s`. **Моё решение.**

### Remote

- `service_client.send_video` и endpoint `/process_video` сервера (`server.py`)
  получают два новых параметра в конце, так же как ранее добавляли параметры VAD.
  Сервер их соблюдает. Web UI контролов не получает.
- Защита от старого сервера та же, что для VAD: при включённой функции
  `_endpoint_parameter_count` меньше отправленного → `ServerTooOldError` до
  загрузки; если endpoint нельзя описать, нужна строка лога `Long pauses:`,
  иначе ошибка до сохранения результата.

## Оставлено исполнителю

- Точная раскладка строки в сетке basic options по конвенциям раскладки GUI
  (`SETTING_ROW_PADY`, без смешивания менеджеров геометрии, проверка в
  настоящем окне).
- Как именно сервер принимает новые параметры в gradio-интерфейсе (по образцу
  `vad_padding_ms`).
- Тесты: `apply_long_pauses` (склейка через короткий звук, звук длиннее допуска
  разрывает, порог, края записи, взаимодействие с remove ranges), CLI, GUI
  `_collect_arguments` в Simple/Advanced, remote-проверка старого сервера.
- Живая проверка: запись с длинной тишиной и уведомлением внутри, длительность
  результата с функцией и без неё.
