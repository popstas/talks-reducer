# VAD speedup mode ("Speedup no voice") — design

Status: draft, awaiting approval. Date: 2026-11-13.

## Зачем

На записях с шумом комнаты, улицы и стуком клавиатуры детектор громкости
(`chunks.detect_loud_frames`, пиковая громкость кадра против `silent_threshold`)
считает шум «звуком», и ускорение тишины почти не срабатывает. Нужен режим, где
обычную скорость получает только **голос**, а всё остальное — `silent_speed`.

Эталонное видео для проверки: `C:\Users\popstas\Videos\VID_20260220_145304_DOLBY_small_480.mp4`
(уличный шум, ускорения тишины не хватает).

## Цели

- Детекция речи моделью Silero VAD вместо порога громкости, когда режим включён.
- Чекбокс **Speedup no voice** в GUI в той же строке, что и **Silence speedup**.
- Пресет **Voice** = Optimal + VAD.
- Продвинутые настройки VAD в Advanced, как минимум отступ (gap) вокруг голоса.
- Основной движок `lite`, плюс два **экспериментальных CLI-only** движка для
  сравнения: `torch` (тот же Silero — сравнение по скорости) и `ten` (TEN VAD —
  другая модель, сравнение по качеству и скорости). Экспериментальные движки,
  скорее всего, удаляются перед релизом; если TEN окажется заметно лучше по
  качеству, решение о нём (с учётом лицензии) принимается отдельно.

## Не цели

- webrtcvad (GMM, путает шум с речью), собственная numpy-реализация сети.
- `torch` и `ten` в GUI, Web UI, OBS dock, remote и в собранном exe/app — только
  CLI из исходников.
- Окно подтверждения установки зависимостей: `lite` ставится вместе с
  программой, экспериментальные движки ставятся вручную через extras.
- GPU-инференс VAD.
- Комбинация VAD + порог громкости (вариант B отклонён).

## Анти-цели (провал, даже если «работает»)

- Установщик Windows растёт больше чем на ~10 МБ.
- Меняется результат обработки с выключенным VAD (дефолтный путь должен остаться
  байт-в-байт прежним).
- VAD включён, а движок недоступен, и обработка **молча** идёт по громкости.
  Должна быть понятная ошибка.

## Подходы (выбран A1, затем уточнён)

- **A. VAD заменяет порог громкости** — голос = sounded, остальное = silent;
  `silent_threshold` при VAD не используется. **Выбран.**
- B. VAD И порог — отклонён: при пороге 0.01 почти ничего не даёт и режет тихую речь.

Поставка движков:

- 1. Опциональные extras + скачивание `onnxruntime` в exe по требованию —
  отклонён: риск, что нативная DLL не загрузится из внешней папки.
- 2. Оба движка в установщике — отклонён: +200 МБ+ ради теста.
- **Выбрано:** `silero-vad-lite` (та же модель Silero, встроенный C++ ONNX
  Runtime, ноль Python-зависимостей, wheel 6.6 МБ Windows / 31 МБ macOS) —
  обычная зависимость, лежит в установщике. `silero-vad` + `torch` и `ten-vad` —
  только CLI из исходников, ставятся вручную через extras.

## Что решено

### Движки

| Движок | Пакет | Где доступен | Установка |
|---|---|---|---|
| `lite` (по умолчанию) | `silero-vad-lite>=0.4.0` | везде: исходники, exe, app, remote-сервер | обычная зависимость `pyproject.toml`/`requirements.txt` |
| `torch` (эксперимент) | `silero-vad` (тянет `torch`, `torchaudio`) | только CLI из исходников | `pip install -e .[vad-torch]` |
| `ten` (эксперимент) | `ten-vad` (только numpy, нативная библиотека внутри, 1.3 МБ) | только CLI из исходников | `pip install -e .[vad-ten]` |

- Лицензия TEN VAD — Apache 2.0 с дополнительными условиями Agora (запрет
  использования, конкурирующего с продуктами Agora). Поэтому `ten-vad` только
  в extra, не в зависимостях и не в установщике.
- Окна у движков разные: Silero — 512 сэмплов (32 мс) при 16 кГц, TEN — hop
  256 сэмплов (16 мс), вход int16. Интерфейс движка возвращает вероятности
  вместе с длиной шага в секундах; постобработка общая.
- Экспериментальный движок не установлен → ошибка с командой установки extra.

- `silero-vad-lite` поддерживает CPython 3.10–3.14. `requires-python` у проекта
  `>=3.9`, поэтому зависимость с маркером `python_version >= "3.10"`; на 3.9 VAD
  выдаёт понятную ошибку. CI и сборки на 3.11.
- PyInstaller: нативная библиотека `silero_vad_lite` должна попасть в бандл
  (хук/`collect_dynamic_libs` при необходимости). Проверяется запуском собранного exe.
- Лицензии проверены: `silero-vad-lite` — MIT (David Zurow), встроенная модель
  Silero VAD v6.2.3 — MIT (Silero Team), копия лицензии лежит в пакете
  (`data/LICENSE.silero`).
- `lite` остаётся при любом исходе сравнения: это единственный движок, который
  можно положить в exe/app и на remote-сервер. Удаление экспериментальных
  движков — отдельный шаг перед релизом, не в этой ветке: в `docs/TODO.md`
  добавляется пункт.

### Пайплайн

- Новый модуль `talks_reducer/vad.py`. Вход — уже извлечённый `audio_data`
  (тот же, что сейчас идёт в `detect_loud_frames`), выход — булев массив по
  **кадрам видео** той же длины `audio_frame_count`. Дальше без изменений:
  `build_chunks` (с существующим `frame_spreadage`), `apply_remove_ranges`, аудио,
  энкод.
- Внутри: моно (среднее каналов) → ресэмпл в 16 кГц → окна движка (32 мс у
  Silero, 16 мс у TEN) → вероятность речи на окно → постобработка как в Silero
  `get_speech_timestamps`: гистерезис по порогу, слияние пауз короче
  `min_silence`, отступ `padding` с каждой стороны → разметка кадров.
- Движки за одним интерфейсом (вероятности + шаг окна), постобработка общая —
  чтобы `lite` и `torch` различались только скоростью инференса, а `ten` —
  только моделью.
- Лог: `Voice detection (lite): 12.3 s, speech 41% of audio` — это и есть
  материал для сравнения движков.
- Новая стадия прогресса `Voice detection:` (через `reporter.task`, единица —
  окна). По GUI Progress Convention у неё должен быть писатель статуса
  (`_apply_stage_status` локально, `_handle_remote_progress` удалённо), а
  `gui/progress.py:STAGE_PROGRESS_RANGES` получает полосу под неё.
- VAD включён, а движок не импортируется → `RuntimeError` с текстом, как
  поставить (не фолбэк на громкость).

### Настройки

`ProcessingOptions` (все с дефолтами, при `vad=False` ничего не меняется):

| Поле | Дефолт | CLI |
|---|---|---|
| `vad: bool` | `False` | `--vad` / `--no-vad` |
| `vad_engine: str` | `"lite"` | `--vad-engine {lite,torch,ten}` (только CLI) |
| `vad_threshold: float` | `0.5` | `--vad-threshold` |
| `vad_padding_ms: int` | `150` | `--vad-padding` |
| `vad_min_silence_ms: int` | `300` | `--vad-min-silence` |

Дефолты padding/min_silence — **мой выбор** (у Silero 30/100 мс, для лекций
слишком резко). Подбираются на эталонном видео.

### Пресеты

- Новое разреженное поле `Preset.vad: Optional[bool]`, метка в
  `PRESET_FIELD_LABELS` — `Speedup no voice`, попадает в `describe_preset` и
  чекбоксы `preset_dialog.FIELD_SPECS`. В CLI `--preset` разворачивается в
  `--vad`/`--no-vad` (explicit > preset > default).
- Настройки VAD (движок, порог, отступ, пауза) в пресет **не** входят — это
  Advanced-уровень. **Мой выбор.**
- Новый дефолтный пресет **Voice** сразу после **Optimal**: поля Optimal + `vad: true`.
- Все дефолтные пресеты, задающие `silent_speed`, получают явное `vad: false` —
  иначе выбор Optimal после Voice оставил бы VAD включённым (та же проблема, что
  с `fps`).
- Миграция `PRESETS_VERSION` 2 → 3, однократно: каждому сохранённому пресету с
  `silent_speed` и без `vad` добавить `vad: false`; если нет пресета с именем
  `Voice` — вставить его после `Optimal` (или в конец). Это сознательное
  исключение из правила «существующие списки не получают новые дефолты».
  **Мой выбор:** значения Voice берутся из захардкоженного `DEFAULT_PRESETS`
  (не из сохранённого Optimal пользователя, который мог быть изменён); если у
  пользователя уже есть пресет с именем `Voice` (без учёта регистра), он не
  трогается и новый не добавляется.

### GUI

- **Speedup no voice** — `ttk.Checkbutton` справа от `basic_preset_control` в
  `basic_presets_frame` (строка Silence speedup). Переменная `vad_var`,
  сохраняется в `GUIPreferences` (`vad_enabled`), зарегистрирована так, чтобы
  `apply_preset_to_gui` двигал её (как `_slider_updaters`), и участвует в
  `match_preset` → **Custom**.
- Строка скрыта в Simple mode вместе с `basic_options_frame`; в Simple VAD
  включается пресетом Voice. **Мой выбор:** в Simple mode `_collect_arguments`
  включает VAD только если выбранный пресет явно задаёт `vad: true`, а
  запомненный `vad_enabled` игнорирует (как уже сделано для Cut video) —
  иначе разреженный пользовательский пресет без поля `vad` молча запустил бы
  VAD без видимого контрола.
- При включённом VAD контрол **Threshold** заблокирован с подсказкой
  «не используется с Speedup no voice».
- Advanced (`advanced_frame`) — группа строк VAD: **VAD threshold**,
  **Voice padding, ms**, **Min pause, ms**. Выбора движка в GUI нет — всегда
  `lite`. Виджеты — по конвенциям проекта (`SegmentedChoice` с custom-слотом там,
  где уместно), все сохраняются в `GUIPreferences`.
- `lite` не импортируется (старый `.venv` без новой зависимости) → ошибка
  обработки с командой `pip install silero-vad-lite`, без окна подтверждения.

### Web UI, OBS dock, remote

- Web UI (`server.build_interface`): чекбокс **Speedup no voice**, управляется
  пресетом; на сервере движок всегда `lite`, Advanced-настройки VAD — дефолты.
- OBS dock: чекбокс в ⚙️ панели, поле `vad` → `dock_server.build_args` → `--vad`.
- Remote из GUI: `service_client.send_video` передаёт `vad`, порог, отступ и
  паузу; сервер их **соблюдает**. Движок на сервере всегда `lite`, поле движка
  в API не передаётся. Нет `lite` на сервере → ошибка
  обработки с понятным текстом, без окна подтверждения. **Мой выбор.**

### Сравнение движков (часть работы)

Прогнать эталонное видео из `.venv` с `--vad --vad-engine lite`, `torch` и
`ten`, плюс без VAD для контраста. В PR — таблица: время стадии
`Voice detection`, общее время, длительность результата, доля речи. Выходные
файлы всех прогонов оставить рядом с исходником под разными именами (например,
суффикс `_vad-lite` / `_vad-ten`), чтобы качество `ten` против `lite` можно было
оценить на слух. Флаг `--vad-dump` (только CLI, эксперимент) пишет найденные
речевые интервалы в `<video>.vad-<engine>.txt` для сравнения разметки
построчно. **Мой выбор**, удаляется вместе с экспериментальными движками.

## Оставлено исполнителю

- Способ ресэмплинга в 16 кГц (должен работать для любого `--sample_rate`, не
  только кратного 16000).
- Точные параметры гистерезиса (Silero использует `threshold - 0.15` для выхода
  из речи).
- Нужен ли PyInstaller-хук для `silero_vad_lite`.
- Где именно в Web UI/доке стоит чекбокс, оформление строк Advanced.
- Как передавать настройки VAD в gradio API без поломки старых клиентов
  (порядок позиционных аргументов).
